1. Executive overview

📘 Beginner Concept — the airport analogy

Imagine an international airport. Passport control (the upstream identity provider csl) checks who you really are. The airline gate agent (the broker ciam) looks at your passport stamp and issues a boarding pass (tokens) that is valid for one specific flight (the application). The flight crew (partner_portal_backend) doesn't re-check your passport; it verifies the boarding pass's hologram (the digital signature) and lets you in. The security perimeter around the whole terminal is the CDN/WAF and reverse proxy.

The enterprise customer-identity (CIAM) platform lets partner users log in to partner_portal without the portal ever handling a password. Authentication is delegated upstream to csl; ISVA acts as the identity broker and OAuth/OIDC authorization server that mints standards-based tokens for the portal. This site documents that platform end to end, flags where it deviates from current best practice, and maps each legacy component to its IBM Security Verify (SaaS) successor.

4. Audit findings summary

⚠️ Security Pitfall — five findings
  1. state/nonce isolation — ciam must create its own state/nonce for the ciam↔csl leg instead of forwarding the portal's state=789.
  2. PKCE S256 not enforced on /authsvc and /authorize.
  3. Malformed nested URL — double ? and missing URL-encoding in /authb/login?appId=…/authorize?appId=123….
  4. Provider ID is https://localhost/sps/oauth/oauth20/15 (iss mismatch) and the legacy ROPC grant is still enabled.
  5. Edge/ACL blocks — Akamai IP allowlist and WebSEAL unauth ACLs on /metadata and /jwks must permit partner_portal_backend.

5. Where this is heading

☁️ IBM Verify SaaS Equivalent
The target is https://<tenant>.verify.ibm.com/oidc/endpoint/default/…: no appliance, no junctions, no Rhino JavaScript. WebSEAL and /mga disappear, the API Protection Definition becomes an Application (OIDC) registration, InfoMap becomes an Identity Source/Access Policy, and pre/post-token scripts become attribute mappings, functions and webhooks.
