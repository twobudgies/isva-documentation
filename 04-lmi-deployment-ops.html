04 · LMI, Deployment & pdadmin

How operators actually change ciam: the Local Management Interface on :9443, why changes don't apply until you Deploy, how to trace the runtime, and how to verify WebSEAL state with pdadmin.

1. Zero-knowledge explanation

📘 Beginner Concept — the restaurant order pad

Editing configuration in the LMI is like writing on an order pad: nothing reaches the kitchen until you press “send order”. That send button is Deploy Pending Changes. Until then your edits sit in a staging area, and the live runtime keeps serving the old configuration. This protects production from half-finished edits — but it also means “I saved it, why doesn't it work?” is the most common ISVA support question.

  • LMI: the web admin console (and REST API) of the appliance, served on port 9443. It is for administrators only.
  • Staged vs deployed: LMI stores edits as pending; Deploy publishes a snapshot to the runtime and WebSEAL and may restart services.
  • Snapshots: point-in-time exports of the whole appliance config; your rollback safety net.
  • pdadmin: the CLI for the policy server: junctions, ACLs, POPs, users, the protected object space.

2. High-level architecture

🏗️ Architecture Deep Dive — separation of planes
User traffic (data plane) enters via Akamai → WebSEAL on 443. Management traffic (control plane) uses LMI on 9443 and pdadmin. The two must be network-separated: LMI should never be reachable through Akamai or the internet.

3. Low-level technical sequence

Runtime tracing and logs

  1. LMI → Monitor → Application Log Files (or Federation Runtime → Logs). Key files: messages.log (runtime, Liberty), trace.log (when tracing is on), WebSEAL request.log, msg__webseald-default.log.
  2. Turn on a trace specification, e.g. com.tivoli.am.fim.*=all:com.ibm.security.access.*=all, reproduce once, then turn it back off — tracing is verbose and can expose tokens and attributes.
  3. Rules can write to the trace with IDMappingExtUtils.traceString("...") (Module 09).
Verify on your appliance
Trace-spec package names and REST paths differ slightly across 10.0.x/11.x. Use the in-LMI help (? icon) for exact strings.

pdadmin cheat sheet

# login
pdadmin -a sec_master -p '********'

# what is running?
pdadmin sec_master> server list
pdadmin sec_master> server task default-webseald-isva-uat01 show /

# junctions
pdadmin sec_master> server task default-webseald-isva-uat01 show /mga
pdadmin sec_master> server task default-webseald-isva-uat01 list

# object space, ACL, POP
pdadmin sec_master> object list /WebSEAL/isva-uat01-default/mga
pdadmin sec_master> object show /WebSEAL/isva-uat01-default/mga/sps/oauth/oauth20/jwks
pdadmin sec_master> acl show unauth_public
pdadmin sec_master> pop show <pop-name>

# reload after changing webseald-*.conf (rarely required; LMI deploy normally does this)
pdadmin sec_master> server task default-webseald-isva-uat01 reload

⚠️ Security Pitfall — LMI exposure & default creds
Confirm 9443 is firewalled from the internet, the default admin password was changed, and mapping rules are reviewed (they run with runtime privileges). Trace logs may contain codes, tokens and PII — restrict and purge them.
