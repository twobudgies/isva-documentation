03 · AAC & Federation Runtime

The “brain” behind ciam: the Advanced Access Control (AAC) and Federation runtime that implements OAuth/OIDC, the authentication service, risk-based (context-based) access and step-up flows. WebSEAL forwards to it through the /mga junction.

1. Zero-knowledge explanation

📘 Beginner Concept — the bank manager

WebSEAL is the teller window: it checks your card and passes simple requests through. When something needs judgement — “this withdrawal is unusual” or “this app wants to act for you” — the teller calls the bank manager in the back office. The manager looks at context (where are you? what device? what time? how risky?) and can say allow, deny or “prove it again with a one-time code” (a step-up obligation). The manager is the AAC runtime.

  • Runtime (“Federation/AAC runtime”): a separate Java server inside the appliance (IBM WebSphere Liberty) that hosts the endpoints below. It is not WebSEAL.
  • Endpoints under /sps (reached as /mga/sps/… via the junction): /authsvc (login flows), /oauth/oauth20/* (authorize, token, introspect, metadata, jwks), /saml20/*, /oidc/*, /apiauthsvc (API-style authentication).
  • Context-Based Access (CBA): policies that score the risk of a request using attributes (IP, geo, device fingerprint, user history) and return a decision plus obligations.
  • Mapping rules: server-side JavaScript (Rhino) hooks that customise behaviour — the three rules used here are explained in Module 09.

2. High-level architecture

🏗️ Architecture Deep Dive — config is a snapshot
Configuration made in LMI sits in a staging area and only reaches the runtime after Deploy Pending Changes (Module 04). Runtime Liberty reloads on deploy. In clustered deployments a primary/secondary config database distributes the same snapshot to every runtime node.

⚠️ Security Pitfall — trusting upstream blindly
Because MFA is performed only at csl, ciam issues tokens based on the upstream assertion. The pre-token rule should verify that the upstream session actually carried the expected authentication level (acr/amr) before minting a code, and reject otherwise. See Module 12.
