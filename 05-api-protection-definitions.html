05 · API Protection Definitions

An API Protection Definition is the “rulebook” of an OAuth/OIDC authorization server inside ISVA. PartnerLink_OIDC_Test defines which grants are allowed, how long tokens live, which mapping rules run and — critically — what the iss claim says.

1. Zero-knowledge explanation

📘 Beginner Concept — the passport office rulebook

A passport office has rules: who may apply, which documents are accepted, how long a passport is valid, and which country name is printed on it. A definition is that rulebook for tokens. One ISVA appliance can host many definitions (many “countries”), each with its own clients, token lifetimes and issuer name.

ROPC defeats the whole point of brokered login: the app (and therefore any attacker who compromises it) would see raw passwords and bypass upstream MFA at csl.

2. High-level architecture

🏗️ Architecture Deep Dive — definition vs client
Definition = server-side policy. Client = a registered app inside a definition. Both must agree: a client can only use grants the definition enables, and its tokens carry the definition's iss.

3. Low-level technical sequence — what the definition decides at /token

Provider ID and the iss claim

The Provider ID becomes the iss value in every id_token and the issuer in /metadata. The audit found it set to https://localhost/sps/oauth/oauth20/15 — an internal value. Clients validating the token compare iss against the URL they used for discovery (https://test.partnerlink.enterprise.com/...), so validation fails or the validator is relaxed (a security regression).

# what the server currently advertises
curl -s https://test.partnerlink.enterprise.com/mga/sps/oauth/oauth20/metadata/PartnerLink_OIDC_Test | jq '{issuer, authorization_endpoint, token_endpoint, jwks_uri}'
# desired
{
  "issuer": "https://test.partnerlink.enterprise.com/mga/sps/oauth/oauth20/metadata/PartnerLink_OIDC_Test",
  "authorization_endpoint": "https://test.partnerlink.enterprise.com/mga/sps/oauth/oauth20/authorize",
  "token_endpoint": "https://test.partnerlink.enterprise.com/mga/sps/oauth/oauth20/token",
  "jwks_uri": "https://test.partnerlink.enterprise.com/mga/sps/oauth/oauth20/jwks/PartnerLink_OIDC_Test"
}
Verify on your appliance
The exact field is labelled “Provider ID” (or Issuer Identifier) under the definition's OpenID Connect settings, and the value is a URL string. Choose any stable external URL on your public host — it need not resolve, but must be identical in iss, metadata and the client's configuration.

⚠️ Security Pitfall — changing the issuer
Changing Provider ID changes iss for every new token, so every relying party must be updated at the same time. Existing, unexpired tokens keep the old iss. Plan a cut-over window and keep access-token lifetimes short before the change.
